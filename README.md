# Pomodoro Alejandro

Помидорный таймер для Chrome (Manifest V3): фазы работы и перерывов, метки сессий, дневная цель, статистика и экспорт. Виджет живёт поверх любой страницы, отсчёт продолжается независимо от того, открыты вкладки или нет.

## Установка

1. `chrome://extensions` → включить **Режим разработчика**.
2. **Загрузить распакованное расширение** → выбрать эту папку.
3. Иконку удобно закрепить на панели — на ней показывается обратный отсчёт.

Требуется Chrome 120 или новее.

## Как пользоваться

| Действие | Что происходит |
| --- | --- |
| Клик по иконке | Показать/скрыть виджет на текущей вкладке |
| **Запустить** | Старт текущей фазы; введённая метка привязывается к сессии |
| **Сбросить** | Прервать фазу и начать её заново (прерванная фаза попадает в журнал) |
| **Пропустить** | Перейти к следующей фазе, не досиживая текущую |
| **Esc** | Закрыть настройки, а если они закрыты — спрятать виджет |

Цикл: работа → короткий перерыв, а каждая N-я работа (N = «сессий в блоке») ведёт к длинному перерыву, после которого счёт блока обнуляется.

**Метки.** Поле «Над чем работаешь?» видно только в рабочей фазе. Метка сохраняется между сессиями и попадает и в журнал, и в дневные агрегаты, поэтому «на что ушла неделя» видно в панели «Неделя».

**Экспорт.** В шапке журнала: **CSV** — построчный журнал для таблиц, **JSON** — полный дамп (настройки, агрегаты, журнал).

## Архитектура

Три файла и один принцип: **источник правды — `chrome.storage`, а не память service worker.**

```
service-worker.js   переходы фаз, алармы, уведомления, бейдж, запись статистики
content-script.js   виджет в Shadow DOM: отрисовка, ввод, экспорт
styles.css          стили, изолированные в shadow root
```

Ключевые решения и почему они такие:

- **Таймер хранит `endsAt`, а не остаток.** Service worker в MV3 умирает после ~30 секунд простоя, и любой счётчик в памяти умирает с ним. Момент окончания — абсолютная величина: сколько бы воркер ни спал, `endsAt - Date.now()` остаётся верным.
- **Один аларм на момент окончания.** `chrome.alarms` — не `setInterval`: Chrome зажимает период минимумом в 30 секунд. Аларм нужен только для того, чтобы разбудить воркер к концу фазы. Секунды рисует content script своим `setInterval`, ему воркер для этого не нужен.
- **`reconcile()`** сверяет сохранённое состояние с часами при пробуждении воркера, срабатывании аларма и старте браузера: время вышло — переходим к следующей фазе, нет — переставляем аларм.
- **`saveTimer()` — единственный способ записать состояние**, и он же перерисовывает бейдж. Забыть обновить бейдж в новой команде негде.
- **Ключ дня строится вручную** (`2026-07-12`) из локальной даты: `toISOString()` дал бы дату по UTC и уводил вечерние сессии в следующий день.

## Схема хранения

| Ключ | Что это | Срок жизни |
| --- | --- | --- |
| `settings` | Длительности, сессий в блоке, дневная цель, автостарт, тема | Постоянно |
| `timer` | Текущая фаза: `phase`, `status`, `endsAt`, `remainingMs`, `startedAt`, `plannedMs`, `completedSessions`, `label` | Пока идёт |
| `history` | Журнал завершённых и прерванных фаз | 30 дней (потолок 2000 записей) |
| `daily` | `{ '2026-07-12': { focusMs, breakMs, sessions, interrupted, labels } }` | Бессрочно |

Вся статистика в интерфейсе считается из `daily`, поэтому обрезка журнала на неё не влияет. Одна запись журнала — около 130 байт, одна дневная сводка — около 75; при квоте `storage.local` в 10 МБ это не проблема даже за годы.

Прерванная фаза короче 30 секунд не записывается — это шум. Пропущенная рабочая сессия не засчитывается ни в дневную цель, ни в прогресс блока, но её фактические минуты попадают в «в фокусе».

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `storage` | Состояние таймера, настройки, статистика |
| `alarms` | Разбудить воркер к концу фазы и для обновления бейджа |
| `notifications` | Сообщить об окончании фазы и достижении цели |

`host_permissions` не нужны: content script объявлен в манифесте декларативно.

## Разработка

Проверить синтаксис:

```sh
node --check service-worker.js && node --check content-script.js
```

После правок — «Обновить» на карточке расширения в `chrome://extensions`. Логи воркера смотреть там же по ссылке **service worker**; логи виджета — в консоли самой страницы.

Комментарии в коде на английском, строки интерфейса — на русском. Формат хранения не зависит от локали, локализуется только отображение.
